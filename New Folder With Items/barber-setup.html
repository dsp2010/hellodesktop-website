03 / REVIEW BEFORE GO-LIVE

A setup you can check.

Review your working brief, then use the scenarios below with the team. A polished demo is only one part of testing a real telephone and booking connection.

Live acceptance checks 8 scenarios · manually reported

These tests do not run on this website. Every result starts as Not yet tested. Change a result only after a person checks the real connected service. A marked result is a review note, not independent verification or activation.

01

Correct service, staff and time

Check a real calendar slot, service duration, opening hours, breaks and the requested member of staff.

02

No double booking

Try the same slot twice, including simultaneous requests. A slot must be checked again when the booking is created.

03

Confirmation follows calendar acceptance

Confirm that an appointment is described as booked only after the calendar accepts it. A failed or timed-out request must not become a confirmation.

04

Change the correct appointment

Identify the existing booking, check the new time, and verify the change in the calendar without leaving duplicate appointments.

05

Cancel the correct appointment

Check the booking identity and cancellation rules. Verify the intended appointment is cancelled and a retry does not affect another booking.

06

A clear route to the team

Test a transfer while staff can answer and while they cannot. Verify the agreed message-taking fallback and destination.

07

No availability or connection failure

Try a fully booked day and an unavailable booking service. The assistant should explain the limit and use the agreed next step.

08

The real telephone journey

Call the actual shop number from a mobile. Check forwarding, voice clarity, interruptions, ending the call and any agreed SMS confirmation.
